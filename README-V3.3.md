# CPU Validation V3.3

本升级面向当前 V3.2.2 + 现场 target_sha256 修复版本。原始测试证据、供应商规格、配置、start.sh、SSH密钥及 OpenHands API Key 均不在包中。server.py 仅接受已知的 target 修复版（8001/18001两种）；不匹配拒绝安装。默认修正为18001。停止网页及所有排队/运行任务后升级，保留备份路径。

## 安装顺序

1. 在共享工程根目录解压两个升级包到不同目录。运行对应 `install_v33.py --target <repo>` 预检，确认后附加 `--apply`。
2. 将 Automation repo 变更同步到现有 Git Sync/Canvas。新增 CPU-13-EnvironmentPrepare、CPU-14-FaultRecovery、CPU-15-ReadinessCheck；检查任务名称、prompt、模型 qianwen、手动触发/定时器、SUT_SUDO_PASSWORD Secret 与 CPU-01 一致。三项默认 INACTIVE，不自行激活。已有 CPU-10/11/12 如缺失，用对应 imports 文件导入并配置；不要重复创建同名任务。禁止将密码提交到 Git。实际 API、Canvas import、Secret 及触发器需现场确认。
3. `cd cpu_ai_validation/web && bash start.sh`，输入被测机 sudo 密码；保留现有本地访问转发。浏览器 Ctrl+Shift+R。新建验收，不复用旧流程/批准会话。
4. 在规格页单独授权启动指定 KVM、正常重启（可不选）、CPU/KVM 负载、I/O 负载。Agent 13 只在关机且 CPU范围/持久绑定匹配时启动一次。14 仅准备失败时派发，记录资源证据；只有明确授权、当前 SSH 超时、持久与运行绑定均符合才发出一次正常重启请求，不强制断电；15 只读复核。自动重试只针对只读就绪检查。
5. 审批前复探测，保留初始差异与准备证据；审批后不因指标 FAIL/WARN/无阈值停止后续独立测试。CPU-02/03/04 的安全子用例由 common/stage_gates.py 校验（身份、CPU、实际绑定及工具等）；仅 TP09 Guest 就绪异常不阻断已经确认安全的宿主实验。脚本仍逐组验证 Guest/负载。没有授权的负载不会执行，缺少前置条件的阶段给出跳过原因。存在不明派发、身份变化或会话失效，不能强行继续。
6. CPU-09 汇总客观结果，CPU-10/11/12 生成分析或显示未生成原因。报告原始证据、图表和数据继续保留。最后单独填写人工验收意见；无条件合格要求完整客观通过，有偏差可记录有条件接受或整改，不能修改客观数据。人工结论单次写入；本地记录不是电子签章。

## 范围及限制

- OpenHands 通过受控命令执行入口，提示词不是操作系统级沙箱；不允许自动改GRUB、IRQ、KVM绑定、安装工具、强制关机或清理任意进程。自动安装、服务重启、精确的残留进程恢复和单项断点复测未实现。
- 现有引擎仍需指定VM定义生成审批设备指纹。身份/配置或启动指纹变化时必须重新审批；仅静态/只读探测可能保留，不能任意绕过。
- 恢复失败仍保留诊断与初始快照；安全前置条件足够时测量其余指标，不承诺故障情况下所有数据都可采集。实际 `virsh reboot` 只代表请求被接受，Guest恢复与请求响应分开记录，不证明实际重启完成。
- 真实 OpenHands、被测机、四组负载、长测及浏览器端尚未联调。离线模拟测试不是实际机器验收结果。

回滚：停止任务和网页，用 `python3 <解压目录>/install_v33.py --target <repo> --rollback <实际BACKUP路径>`。修改过已安装文件时拒绝覆盖。重开新流程。
